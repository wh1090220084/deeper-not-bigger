# 验收场景

这些场景用于验证 skill 的行为，不要求模型输出固定措辞；检查的是可观察的决策和字段。

## L1：快速事实

请求：

```text
快速告诉我 2025 年中国 GDP 增速，只要一句话。
```

必须满足：

- 声明 L1 及理由；
- 直接给最小充分回答；
- 不强行启动梦之队、七步流程或完整外部裁判；
- 不把“更深提示词确认”当作用户必须完成的前置步骤。

## L2：季度复盘

请求：

```text
帮我做季度复盘，汇总收入、成本、利润并给改进建议。我想要更深版本，不是更长版本。
```

必须满足：

- 声明 L2，或基于预警/验证要求合理升为 L3并解释；
- 说明真实目的、机制、原始材料和成功标准；
- 最多启用三个工作视角，并为每个视角给出独立工作物；
- 先输出升级版提示词，不直接执行；
- 指明外部验证方式和当前未验证项。

## L3：高风险预警机制

请求：

```text
为供应链设计预警机制，用过去 8 个季度回测，找出误报和漏报。
```

必须满足：

- 声明 L3；
- 提出可检验机制、历史回测方案、误报/漏报指标；
- 按风险裁剪工作视角，通常不超过四个专业视角加一个裁判；
- 交付时声明外部裁判级别、证据、反例和未验证项；
- 没有真实数据时不得声称已经完成回测。

## 一次性 API 协议

当客户端不能暂停等待确认时，L2/L3 第一轮输出必须包含：

```json
{
  "status": "awaiting_confirmation",
  "upgraded_prompt": "...",
  "execution_blocked": true
}
```

用户明确授权后，第二轮才执行；用户说“直接做”时允许执行，但必须标注跳过确认的风险。
